# FGO 羁绊加成组队计算器

在 Cost 限制内组合**羁绊加成礼装**与**从者**，最大化全队总羁绊获取的 Web 工具。

## 背景机制

当前游戏里有 11 张「+4% / 满破 +20%」的羁绊礼装，每张对应不同的**特性条件**（如
「混沌且七骑士」「秩序·善」「活在当下的人类」「星或恶」「兽科从者」「Saber/Rider/Caster 职阶」等）。
这类礼装的效果是：**关卡通关时，全队中符合该特性的从者获得额外羁绊**（多张可叠加）。

因此最优组队 = 选对礼装 + 带对从者（让尽可能多的上阵从者命中礼装特性）。

## 功能

- 勾选持有的羁绊礼装（数量 / 满破张数）、持有的从者（默认全持有）
- 锁定必须上阵的从者，其余位置由优化器自动补位（可选：自动选择从者以最大化特性覆盖）
- 助战位：自动从可借礼装中选最优（满破午茶 +15% 全队，或特性礼装）；好友助战的从者与礼装 **cost 不计入自己的 Cost 上限**（游戏机制）
- 礼装 cost 只由稀有度决定（5★=12 / 4★=9），**满破不改变 cost**
- **Top 3 备选方案对比**：跨助战礼装/礼装组合给出 3 套方案，附对比表
- **从者筛选**：按稀有度 / 职阶（多选 chips）/ 特性（多选 = 需同时满足）/ 关键词；筛选**同时约束组队结果**——被筛掉的从者不会出现在推荐队伍中（锁定的从者除外，不满足筛选时会提示）
- 优化目标：全队总羁绊加成最大化（`Σ每人加成`），约束：总 Cost ≤ 上限
- 特性匹配支持复合特性推导（属性/性别/副属性/职阶）与别名（FSN从者、兽科从者）
- 「持有灵衣之人」特性：只要从者有灵衣就默认视为已解锁（从 Mooncell 页面的「灵衣开放」区块自动解析，无需手动标记）
- **配置记忆**：持有礼装/从者、锁定、灵衣、参数设置自动保存在本机浏览器（localStorage）；
  「复制配置链接」可把配置打包进 URL（base64url 压缩，只存较小一侧的从者集合），分享给他人或收藏

## 使用

```bash
npm install            # 首次
npm run dev            # 开发服务器 http://127.0.0.1:5173 (含数据更新 API)
npm run build && npm run serve   # 生产: 构建后 http://127.0.0.1:4173
npm test               # 运行测试 (优化器单测 + 真实数据集成测试)
```

## 数据与一键更新

- 数据抓取后**保存在本地** `data/` 与 `public/data/`（前端直接加载，启动不爬虫）。
- 页面右上「**一键更新数据**」按钮会重新抓取 Mooncell（约 2~3 分钟）：
  - 开发模式：由 Vite 插件中间件处理 `POST /api/refresh`
  - 生产模式：由 `node server.mjs` 处理
  - 爬虫会把最新结果写入 `data/`、`public/data/`、`dist/data/`（若存在），页面随后自动重载新数据
- 命令行方式：`npm run scrape`（之后如使用生产模式需重新 `npm run build`）
- 页面会显示数据文件的最后更新时间（`GET /api/status`）

```

```

## 优化算法

1. 固定助战礼装时：从「锁定从者 + 最便宜补位」出发，交替迭代：
   - 礼装选择：0/1 背包（cost × 张数约束），特性礼装价值 = 加成 × 命中从者数；
   - 从者选择：按已选礼装对每个可用从者打分，再做一次带 Cost 约束的背包；
   - 直到队伍不再变化（单调收敛）。
2. 助战位：枚举每个可借礼装（含无），取总加成最高者。
3. Top-N：对每个助战选项收敛后的队伍，用 Top-K 背包取多个礼装组合，跨选项去重排序取前 3。

## 已知限制

- 从者特性取 Mooncell 页面首个「基础数值」形态；同名异形态（泳装/Alter/异格）以页面标题区分。
- 「持有灵衣之人」特性从 Mooncell「灵衣开放」区块自动解析（有灵衣即视为已解锁）；个别从者若数据未收录灵衣区块，可人工核对。
- 特性条件提取依赖 Mooncell 文本格式；新礼装若格式变化需人工核对 `data/ces.json`。
- 「一键更新」需要本机有 `python3`。
