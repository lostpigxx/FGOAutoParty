# FGO 羁绊加成组队计算器

在 Cost 限制内组合**羁绊加成礼装**与**从者**，最大化全队总羁绊获取的 Web 工具。当前版本 v0.3.0（数据抓取自 [Mooncell](https://fgo.wiki)）。

## 背景机制

游戏里有若干「+4% / 满破 +20%」的**特性类羁绊礼装**，每张对应不同的**特性条件**（如
「混沌且七骑士」「秩序·善」「秩序的女性」「活在当下的人类」「星或恶」「兽科从者」「Saber/Rider/Caster 职阶」等），
另有 5%/10%/15% 无条件礼装（名侦探/晚餐时光/午餐时光/午茶时光等）。
这类礼装的效果是：**关卡通关时，全队中符合该特性的从者获得额外羁绊**（多张可叠加）。

因此最优组队 = 选对礼装 + 带对从者（让尽可能多的上阵从者命中礼装特性）。

## 功能

**组队与优化**
- 勾选持有的羁绊礼装（默认只看 5★；每张至多 1 张，勾选即默认满破，可取消满破）
- 勾选持有的从者（默认全不选，可按职阶/特性筛选后反选）；锁定必须上阵的从者，其余由优化器补位
- **助战位**：下拉可选「无 / 自动选最优 / 指定某张好友礼装」；**冠位第二助战位**同理；好友助战 cost **不计入自己的 Cost 上限**（游戏机制）
- **冠位战 / 普通模式一键预设**：冠位战 = 上阵 5 / 礼装 6（第 6 张免费）/ 冠位助战自动选最优；普通 = 5 / 5 / 无
- **深度搜索开关**（默认开）：多起点收敛逃逸局部最优——多职阶搭配时显著更优（实测约 +15%），单职阶可关闭加速
- 结果给出 **智能方案 / 加成最佳 / cost最佳** 多套方案对比；智能方案 = 加成第一、同加成尽量上高星

**礼装与筛选**
- 礼装列表按 ID 倒序（国服未实装的最新礼装聚顶，方便快速取消勾选）；自动剔除 <5% 鸡肋礼装
- 从者按稀有度 / 职阶（多选）/ 特性（多选 = 需同时满足）/ 关键词筛选；筛选**约束组队结果**
- 特性匹配支持复合特性推导（属性/性别/副属性/职阶）与别名（FSN从者、兽科从者）
- 礼装 cost 只由稀有度决定（5★=12 / 4★=9），**满破不改变 cost**；礼装数上限可大于上阵人数（超出部分免费，适配冠位战）

**战斗形象（形态）**
- 少数从者（95 名）不同**战斗形象/灵衣**下 属性/特性 不同（如 U－奥尔加玛丽 形象1/2 为 恶·星，形象3 为 善·人·活在当下的人类；玛修 还有 Paladin 家族）
- 这类从者卡片有**形态下拉**：默认「形态·自动」= 搜索所有形态、按全队礼装自动选加成最高的形象，并在结果卡提示「⚠ 需使用『战斗形象3』形态」；也可手动锁定（持久化）
- 特性筛选/搜索按任意形态命中；自动形态下按「每人独立取最优形态」精确计算，**防止同一从者被两张不同特性的 20% 礼装各命中一次造成高估**
- 马修（玛修·基列莱特）COST=0 覆盖：其全部战斗形象均不占 Cost（此前按稀有度误算）
- 「持有灵衣之人」：有灵衣的从者默认视为已解锁（来自 Mooncell「灵衣开放」区块），国服未实装的可在卡片上取消勾选

**配置保存 / 分享**
- 持有礼装/从者、锁定、灵衣反选、形态选择、全部设置自动保存在本机浏览器（localStorage）
- 「导出配置」：弹窗确认文件名 → 由本机服务写入项目根目录 `settings/` 文件夹（服务不可用时自动回退浏览器下载）
- 「导入配置」：从本地 JSON 文件完整恢复
- 「复制配置链接」：打包进 URL（base64url 压缩，只存较小一侧的从者集合），可收藏或分享

## 使用

### 开发（源码目录）

```bash
npm install                 # 首次
npm run dev                 # 开发服务器 http://127.0.0.1:5173
                            #   (Vite 中间件提供 /api/refresh、/api/status、/api/config/save，
                            #   数据写入当前目录 data/ 与 settings/)
npm test                    # 运行测试 (vitest: 优化器 + 形态 + 配置 单测与真实数据集成)
npm run build && npm run serve   # 生产: 构建后 http://127.0.0.1:4173
```

### 发布版（release zip，Windows / macOS / Linux）

1. 安装 [Node.js](https://nodejs.org)（LTS 即可，zip 内不捆绑运行时）
2. 解压 zip，双击 `start.bat`（或命令行 `node server.mjs`，可用 `PORT=xxxx` 换端口）
3. 浏览器自动打开 http://127.0.0.1:4173，关闭黑窗口即停止
4. 「导出配置」的文件会保存到**解压目录的 `settings/` 文件夹**
5. 「一键更新数据」需要本机有 `python3`（可选；未安装时页面会提示）

> 说明：浏览器下载无法选择任意目录，导出配置依赖本机服务写 `settings/`；若直接以 `file://` 打开页面（无服务），导出会自动回退为普通浏览器下载。

## 数据与一键更新

- 数据抓取后保存在本地 `data/` 与 `public/data/`（前端直接加载，启动不爬虫）。
- 页面「一键更新数据」重新抓取 Mooncell（约 2~3 分钟）：
  - 开发模式：Vite 插件中间件处理（写入 `process.cwd()`）
  - 发布模式：`node server.mjs` 处理（写入其所在目录）
  - 爬虫同步写入 `data/`、`public/data/`，生产构建的 `dist/data/` 需重新打包或手动更新
- 命令行方式：`npm run scrape`
- 页面显示数据最后更新时间（`GET /api/status`）

## 优化算法

1. **多起点**：从确定性种子集（最便宜 / 最高星 / 特性·职阶定向 / 固定随机）分别出发做交替迭代，
   每个起点 × 每种助战选项取全局最优（深度搜索开关关闭时退化为默认单起点）。
2. 固定助战礼装下的交替迭代：
   - 礼装选择：0/1 背包（cost × 张数约束），特性礼装价值 = 加成 × 命中从者数（形态从者按任意形态乐观计）；
   - 从者选择：按已选礼装对每个可用从者打分（形态从者取最优形态），再做一次带 Cost 约束的背包；
   - 直到队伍不再变化（单调收敛）。
3. **形态精确计算**：队伍确定后，含形态从者时对礼装组合做**精确子集枚举**，
   每人按其 argmax 形态计加成（避免"星/恶"与"善/活在当下"两张 20% 靠不同形象命中同一人而被高估）。
4. 助战位枚举（含无），跨选项去重排序 → 输出 智能方案 / 加成最佳 / cost最佳（cost最佳用子集和 DP 尽量吃满 cost）。

## 已知限制

- 战斗形象形态数据来自 Mooncell 的「特性N备注」与「基础数值」散文，按规则自动归类（形象 1/2/3、灵衣、第二灵基家族、背景说明类备注）；
  若个别从者与游戏内不符，欢迎反馈以便人工补丁进爬虫。
- 「持有灵衣之人」自动解析自「灵衣开放」区块；个别从者数据未收录时可人工核对。
- 特性条件提取依赖 Mooncell 文本格式；新礼装若格式变化需人工核对 `data/ces.json`。
- 一键更新与数据抓取需要本机有 `python3`。
